# 短视频文案

一句话选题 → 一套可以直接开拍的文案。

这套技能是**引擎 + 预设**的结构：方法论在这里，风格在 `presets/` 里，当前选择在 `profile.md` 里。

---

## 0. 先读两个东西

1. `profile.md` —— 当前选择（platform / category / tone / duration / density / person / cta / banned）
2. 按 profile 去对应预设文件里读**它选中的那一节**，不要整份读

| profile 字段 | 去读哪 | 只读哪一节 |
|---|---|---|
| `platform` | `presets/platforms.md` | 同名小节（抖音/小红书/视频号/B站/通用） |
| `category` | `presets/categories.md` | 同名小节 |
| `tone` | `presets/tones.md` | 同名小节 |
| 钩子 | `presets/hooks.md` | 按选题类型挑 1–2 类 |

profile 里的值优先于本文件的一切默认；用户当场改口的，以当场为准。

---

## 1. 默认流程：先出稿，再收参数

用户给一句话时，**不要先问一串问题**。先用当前 profile（没有就用：通用 / 清晰直接 / 30 秒）出一版完整的，让他看见东西，再问。

### 第一步：出通用稿

四件套齐全（口播 + 分镜 + 发布文案），时间按 `presets/timing.md` 算。
开头注明一句：**「这是通用版，没做平台特化」**——不然用户会以为这就是最终稿。

### 第二步：固定四问

只问这四个，按顺序，每个都给选项。不要追加别的问题。

> **1. 平台**：抖音 / 小红书 / 视频号 / B站 / 就用通用？
> —— 决定节奏、语速、CTA
>
> **2. 调性**：犀利 / 亲切 / 幽默 / 克制专业 / 保持清晰直接？
> —— 决定句长、动词、和观众的距离
>
> **3. 结构**：口播三段 / 科普（结论先行 + 机制）/ 故事（经历 + 提炼）/ 剧情（冲突 + 反转）？
> —— 决定段落顺序和占比
>
> **4. 反转与钩子**：不加 / 中段加一个反常识转折 / 结尾留反转 / 双钩子（前 3 秒停手 + 8 秒留人）？
> —— 决定完播设计

问完补一句：**「直接回 1/2/3 这种编号，或者一句话说都行，我按这个重写。」**

### 第三步：重写

- **只改受影响的段落**，用户认可的部分保留
- 开头用一行说明改了什么：`平台→抖音，语气→犀利，时长 30→15 秒，中段加反常识转折`
- 重写后时间必须重算，不能沿用旧表

### 第四步：要不要记住

用户说"以后都这样""记住""默认改成"→ 按 §5 写 `profile.md` 并回报。

### 例外

| 情况 | 处理 |
|---|---|
| 用户一次就把平台/调性说清了 | 跳过问卷，直接出定向稿 |
| 用户说"先给我看通用的" | 只出通用稿，不问 |
| 用户只要钩子不要全文 | 只给 5 条候选钩子，让他挑 |

## 1b. 一句话里缺什么

| 缺什么 | 怎么处理 |
|---|---|
| 给谁看 | 从选题反推最可能人群，**明说假设** |
| 要什么动作 | 用 profile 的 `cta` |
| 多长 | 用 profile 的 `duration` |
| 什么平台 | 用 profile 的 `platform`，没有就按"通用" |

**通用稿阶段只补一个最关键的假设，不要连环追问。** 追问放在第二步的固定四问里。

## 2. 组装：四个预设怎么叠

顺序不能乱，每一层解决一个不同的问题：

```
platform  → 决定节奏、语速、CTA（外形）
category  → 决定段落顺序和占比（骨架）
tone      → 决定句子长度、动词、距离（皮肤）
hooks     → 决定前 3 秒（门）
```

冲突时的优先级：**platform > category > tone**。
比如小红书要"慢"，但带货要"密"，取中间值，并在文末说明你做了取舍。

### 常用组合（可以直接推荐给用户）

| 目标 | 组合 |
|---|---|
| 抖音爆款感 | 抖音 + 知识科普 + 犀利 + 反常识钩子 |
| 小红书种草 | 小红书 + 带货 + 亲切 + 痛点场景 |
| 视频号信任 | 视频号 + 个人IP + 克制专业 + 故事在场 |
| B站硬核 | B站 + 知识科普 + 克制专业 + 具体数字 |
| 新手最稳 | 通用 + 口播 + 清晰直接 + 反常识 |

## 3. 输出四件套

### 3.1 口播稿（时间必须算，不能估）

按 `presets/timing.md` 算，表格必须带**字数**列，方便核对：

| 时间 | 字数 | 台词 |
|---|---|---|
| 0.0–1.9s | 6 | 你越补觉，越累。 |

算法：`字数 / 语速 + 0.2×逗号 + 0.35×句号`，逐句累加。
**先按容量表控制总字数，再算时间**；顺序反了必然超时。

直接跑脚本生成，不要手算：

```bash
node scripts/timing.mjs --rate 4.5 "你越补觉，越累。" "欠的不是时间，是节奏。"
```

末尾时间与 `duration` 的误差必须 ≤ 0.5 秒。超了删字，不要靠念快来糊。

### 3.2 分镜表（时间从口播复制）

| # | 时间 | 画面 | 屏幕文字 | 备注 |
|---|---|---|---|---|

- 一句台词一个镜头：时间列**直接照抄口播表**，不许独立分配
- 一句拆两个镜头：编号写 `1a` / `1b`，父级时间不变，子镜头相加必须等于原句时长
- 单镜头 < 1.2 秒合并，> 6 秒拆分

画面只写**能拍出来的东西**。不要"有氛围感的空镜"。

### 3.3 content.json（可选，给视频流水线）

结构是 `scenes` 数组，类型、上限、映射规则见 `presets/scenes.md`。

```json
{
  "style": "simple",
  "title": "≤12 字（用于草稿命名）",
  "scenes": [
    { "type": "title", "kicker": "≤16 字", "text": "≤10 字", "note": "≤18 字" },
    { "type": "point", "text": "≤12 字", "note": "≤20 字" },
    { "type": "stat",  "items": [{ "value": 15, "suffix": "s", "label": "≤6 字" }] },
    { "type": "quote", "text": "≤12 字", "note": "≤20 字" },
    { "type": "outro", "kicker": "≤8 字", "text": "≤5 字", "note": "≤20 字" }
  ]
}
```

硬规则：

1. **一场景一句话**。超过 12 字就在逗号处拆成两个 `point`，不要指望视频侧帮你压
2. 12 字带标点 ≈ 3.4 秒，已经是单镜头上限。再多，视频侧会压字号，画面就难看了
3. `stat` 的数字必须来自正文。凑不出就 2 张，别硬凑
4. 段数：15 秒 5–8 段，30 秒 8–14 段。段数就是剪辑的颗粒度
5. 首段必须是 `title`，末段必须是 `outro`
6. 写完**必须**跑校验，不通过不要交给视频侧：

```bash
node scripts/check-scenes.mjs content.json
```

校验会报：类型非法、字数超限、数据卡超过 3 张、首尾场景缺失、估算时长越界。

### 3.4 发布文案

标题（≤20 字）+ 3–5 个标签 + 一句评论区引导。

### 3.5 动效素材检查（只在文案要用动效时）

分镜里写了 `effect` 的 id，说明成片要叠透明动效。出稿前查一次素材库：

```powershell
cd <video-studio>
.\check-effects.ps1 -Human
```

判定与动作：

| 结果 | 动作 |
|---|---|
| 脚本不存在 | 用户没装视频流水线 → **跳过，不要当错误**，正常出稿 |
| `installed=true` | 素材齐，继续 |
| `installed=false` | **先提醒再问**（见下），不要闷头出稿 |

提醒话术：

> 你还没有生成动效素材库（9 个，约 196 MB）。要现在生成吗？大约 2.5 分钟。

- 用户同意 → 执行 `cd video-studio; .\make-effects.ps1`，完成后汇报"生成了 N 个，用时 X 秒"
- 用户拒绝或说以后再说 → 照常出稿，并在结尾注明：**动效层将被跳过，成片没有扫光/光圈等效果**

**不要在用户没同意的情况下去跑生成**（2.5 分钟、占 196MB，属于重操作）。

## 4. 自检

- [ ] 前 3 秒是钩子，不是自我介绍
- [ ] 钩子属于 hooks.md 里明确的一类，没有串类
- [ ] 有一句能被截图单独转发的话
- [ ] 至少一个具体数字，且正文兑现了
- [ ] 口播每句 ≤ 15 字，按语速念一遍不超时
- [ ] 全篇只有一个调性，没有中途变脸
- [ ] 结构符合所选品类的段落占比
- [ ] 无绝对化用语（最/第一/根治/百分百）
- [ ] 医疗、金融、教育类没有效果承诺
- [ ] 命中 `banned` 里的词？命中就重写那句
- [ ] **要出片时**：`scenes` 每段 ≤ 12 字，首段 title、末段 outro
- [ ] **要出片时**：`node scripts/check-scenes.mjs content.json` 通过

## 5. 反馈怎么改

**改预设，不改引擎。**

| 用户说 | 改哪里 |
|---|---|
| 太长了 / 太短 | `duration` |
| 太官方 / 太冲 / 太油 | `tone` |
| 不像小红书 / 像抖音 | `platform` |
| 信息太密 / 太空 | `density` |
| 结构不对 | `category` |
| 开头不行 | 换 hooks 的类别 |
| 这个词别说 | `banned` |

### 临时改 vs 永久改（重要）

| 用户怎么说 | 你做什么 | 是否落盘 |
|---|---|---|
| "这版改成小红书" | 只按新参数重写这一版 | ❌ 不写文件 |
| "以后都用小红书" / "记住" / "默认改成" | **必须用编辑工具改 `profile.md`** | ✅ 写文件 |
| "太冲了" / "太油了" | 判断是临时还是长期，问一句或按长期处理 | ✅ 写文件 |

**只说不写 = 没改。** 会话结束，上下文就没了，下次还是旧参数。

落盘时必须做三件事：

1. 改 `profile.md` 里对应的那一行
2. 在 `profile.md` 的「改动记录」末尾追加一行：`- YYYY-MM-DD 把 tone 从 X 调成 Y（原因）`
3. 回给用户一句："已写入 profile.md：`tone: 犀利`"

### 预设里没有的值怎么办

用户要 `platform: 知乎`，但 `presets/platforms.md` 只有四个平台：

1. 先按最接近的写（知乎 ≈ B站长文 + 克制专业），**说明你做了近似**
2. 问一句要不要把它加进 `presets/platforms.md`
3. 要加就照现有格式补一节，不要塞进 `SKILL.md`

如果用户连续三次在同一维度上调，说明预设本身不够细，才考虑改 `presets/` 里的那一节。

如果用户连续三次在同一维度上调，说明预设本身不够细，才考虑改 `presets/` 里的那一节。

## 6. 拆解模式（可选）

用户给一条**参考视频**（链接或文字稿）而不是选题时，走 `references/analysis.md`：
输出 hook 类型、结构分段、风格标签、爆款原因、3 个改写方向。

---

## 7. 边界

- 不编数据。没给数字就用可验证的模糊量，或者直接问。
- 医疗、金融、教育不写具体效果承诺。
- 不确定的事实标"待核实"，不写成结论。
- 不写"最/第一/唯一"这类绝对化表述，除非有可核验的来源。
