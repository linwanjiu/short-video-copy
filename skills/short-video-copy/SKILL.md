# 短视频文案

一句话选题 → 一套可以直接开拍的文案。

这套技能是**引擎 + 预设**的结构：方法论在这里，风格在 `presets/` 里，当前选择在 `profile.md` 里。

---

## 0. 先读两个东西

1. `profile.md` —— 当前选择（platform / category / tone / duration / density / person / cta / banned）
2. 按 profile 去对应预设文件里读**它选中的那一节**，不要整份读

| profile 字段 | 去读哪 | 只读哪一节 |
|---|---|---|
| `platform` | `presets/platforms.md` | 同名小节（抖音/小红书/视频号/B站/通用） |
| `category` | `presets/categories.md` | 同名小节 |
| `tone` | `presets/tones.md` | 同名小节 |
| 钩子 | `presets/hooks.md` | 按选题类型挑 1–2 类 |

profile 里的值优先于本文件的一切默认；用户当场改口的，以当场为准。

---

## 1. 默认流程：先出稿，再收参数

用户给一句话时，**不要先问一串问题**。先用当前 profile（没有就用：通用 / 清晰直接 / 30 秒）出一版完整的，让他看见东西，再问。

### 第一步：出通用稿

四件套齐全（口播 + 分镜 + 发布文案），时间按 `presets/timing.md` 算。
开头注明一句：**「这是通用版，没做平台特化」**——不然用户会以为这就是最终稿。

### 第二步：固定四问

只问这四个，按顺序，每个都给选项。不要追加别的问题。

> **1. 平台**：抖音 / 小红书 / 视频号 / B站 / 就用通用？
> —— 决定节奏、语速、CTA
>
> **2. 调性**：犀利 / 亲切 / 幽默 / 克制专业 / 保持清晰直接？
> —— 决定句长、动词、和观众的距离
>
> **3. 结构**：口播三段 / 科普（结论先行 + 机制）/ 故事（经历 + 提炼）/ 剧情（冲突 + 反转）？
> —— 决定段落顺序和占比
>
> **4. 反转与钩子**：不加 / 中段加一个反常识转折 / 结尾留反转 / 双钩子（前 3 秒停手 + 8 秒留人）？
> —— 决定完播设计

问完补一句：**「直接回 1/2/3 这种编号，或者一句话说都行，我按这个重写。」**

### 第三步：重写

- **只改受影响的段落**，用户认可的部分保留
- 开头用一行说明改了什么：`平台→抖音，语气→犀利，时长 30→15 秒，中段加反常识转折`
- 重写后时间必须重算，不能沿用旧表

### 第四步：要不要记住

用户说"以后都这样""记住""默认改成"→ 按 §5 写 `profile.md` 并回报。

### 例外

| 情况 | 处理 |
|---|---|
| 用户一次就把平台/调性说清了 | 跳过问卷，直接出定向稿 |
| 用户说"先给我看通用的" | 只出通用稿，不问 |
| 用户只要钩子不要全文 | 只给 5 条候选钩子，让他挑 |

## 1b. 一句话里缺什么

| 缺什么 | 怎么处理 |
|---|---|
| 给谁看 | 从选题反推最可能人群，**明说假设** |
| 要什么动作 | 用 profile 的 `cta` |
| 多长 | 用 profile 的 `duration` |
| 什么平台 | 用 profile 的 `platform`，没有就按"通用" |

**通用稿阶段只补一个最关键的假设，不要连环追问。** 追问放在第二步的固定四问里。

---

## 2. 组装：四个预设怎么叠

顺序不能乱，每一层解决一个不同的问题：

```
platform  → 决定节奏、语速、CTA（外形）
category  → 决定段落顺序和占比（骨架）
tone      → 决定句子长度、动词、距离（皮肤）
hooks     → 决定前 3 秒（门）
```

冲突时的优先级：**platform > category > tone**。
比如小红书要"慢"，但带货要"密"，取中间值，并在文末说明你做了取舍。

### 常用组合（可以直接推荐给用户）

| 目标 | 组合 |
|---|---|
| 抖音爆款感 | 抖音 + 知识科普 + 犀利 + 反常识钩子 |
| 小红书种草 | 小红书 + 带货 + 亲切 + 痛点场景 |
| 视频号信任 | 视频号 + 个人IP + 克制专业 + 故事在场 |
| B站硬核 | B站 + 知识科普 + 克制专业 + 具体数字 |
| 新手最稳 | 通用 + 口播 + 清晰直接 + 反常识 |

## 3. 输出：默认只给文案

**别一上来就堆一堆东西。** 默认只输出两样：文案、发布文案。分镜表要不要，问过再给。

### 3.1 文案（默认交付，唯一必给的）

带时间轴的口播稿，三列：

| 时间 | 字数 | 台词 |
|---|---|---|
| 0.0–1.9s | 6 | 你越补觉，越累。 |

- 时间按 `presets/timing.md` 算，不要手估；直接跑 `node scripts/timing.mjs --rate <语速> "台词1" "台词2"`
- **标点与语句严格按 `presets/punctuation.md`**：全角标点、单句 ≤ 15 字、一句最多 2 个逗号
- 末尾时间与目标时长误差 ≤ 0.5 秒。超了删字，不要靠念快来糊
- 交付时不要再附 JSON、不要附分镜，除非用户要

### 3.2 发布文案（默认交付）

标题（≤ 20 字）+ 3–5 个标签 + 一句评论区引导。

### 3.3 交付后必须问一句

文案给完，紧接着问：

> 需要我按这段文案出一份分镜表吗？（每句话配什么画面、屏幕文字、时间点）

- 用户说要 → 出 3.4
- 用户说不用，或者没回应 → **到此为止**
- 不要顺手给 content.json，不要问"要不要出片"

### 3.4 分镜表（仅当用户明确要）

| # | 时间 | 画面 | 屏幕文字 | 备注 |
|---|---|---|---|---|

- 时间列**直接照抄 3.1 的时间**，不许独立分配
- 一句台词一个镜头；一句拆两个就写 `1a`/`1b`，两者相加必须等于原句
- 单镜头 < 1.2 秒合并，> 6 秒拆分
- 画面只写**能拍出来的东西**，不写"有氛围感的空镜"

### 3.5 动效检查（仅当用户明确要出片）

只有用户说"要出片""给我草稿"才做：

```powershell
cd <video-studio>
.\check-effects.ps1 -Human
```

| 结果 | 动作 |
|---|---|
| 脚本不存在 | 用户没装视频流水线 → 跳过，不当错误 |
| `installed=true` | 继续 |
| `installed=false` | 先提醒再问，不要闷头生成 |

> 你还没有生成动效素材库（9 个，约 196 MB）。要现在生成吗？大约 2.5 分钟。

用户没同意就不要跑生成。

### 3.6 明确不做的事

- **不输出 `content.json` / `scenes`**：那是视频侧的结构，文案侧不该背这个
- 不主动给分镜，不主动提"要不要出片"
- 不替用户决定平台和调性——那在 `profile.md` 里

## 4. 自检

- [ ] 前 3 秒是钩子，不是自我介绍
- [ ] 钩子属于 hooks.md 里明确的一类，没有串类
- [ ] 有一句能被截图单独转发的话
- [ ] 至少一个具体数字，且正文兑现了
- [ ] 口播每句 ≤ 15 字，按语速念一遍不超时
- [ ] 全篇只有一个调性，没有中途变脸
- [ ] 结构符合所选品类的段落占比
- [ ] 无绝对化用语（最/第一/根治/百分百）
- [ ] 医疗、金融、教育类没有效果承诺
- [ ] 命中 `banned` 里的词？命中就重写那句
- [ ] 标点全是全角，没有半角 `,.!?`
- [ ] 引号统一（「」或“”），省略号是 `……`，破折号是 `——`
- [ ] 没有一逗到底的长句，每句 ≤ 15 字
- [ ] 数字格式统一（15秒 / 73%），英文前后有空格

## 5. 反馈怎么改

**改预设，不改引擎。**

| 用户说 | 改哪里 |
|---|---|
| 太长了 / 太短 | `duration` |
| 太官方 / 太冲 / 太油 | `tone` |
| 不像小红书 / 像抖音 | `platform` |
| 信息太密 / 太空 | `density` |
| 结构不对 | `category` |
| 开头不行 | 换 hooks 的类别 |
| 这个词别说 | `banned` |

### 临时改 vs 永久改（重要）

| 用户怎么说 | 你做什么 | 是否落盘 |
|---|---|---|
| "这版改成小红书" | 只按新参数重写这一版 | ❌ 不写文件 |
| "以后都用小红书" / "记住" / "默认改成" | **必须用编辑工具改 `profile.md`** | ✅ 写文件 |
| "太冲了" / "太油了" | 判断是临时还是长期，问一句或按长期处理 | ✅ 写文件 |

**只说不写 = 没改。** 会话结束，上下文就没了，下次还是旧参数。

落盘时必须做三件事：

1. 改 `profile.md` 里对应的那一行
2. 在 `profile.md` 的「改动记录」末尾追加一行：`- YYYY-MM-DD 把 tone 从 X 调成 Y（原因）`
3. 回给用户一句："已写入 profile.md：`tone: 犀利`"

### 预设里没有的值怎么办

用户要 `platform: 知乎`，但 `presets/platforms.md` 只有四个平台：

1. 先按最接近的写（知乎 ≈ B站长文 + 克制专业），**说明你做了近似**
2. 问一句要不要把它加进 `presets/platforms.md`
3. 要加就照现有格式补一节，不要塞进 `SKILL.md`

如果用户连续三次在同一维度上调，说明预设本身不够细，才考虑改 `presets/` 里的那一节。

如果用户连续三次在同一维度上调，说明预设本身不够细，才考虑改 `presets/` 里的那一节。

## 6. 拆解模式（可选）

用户给一条**参考视频**（链接或文字稿）而不是选题时，走 `references/analysis.md`：
输出 hook 类型、结构分段、风格标签、爆款原因、3 个改写方向。

---

## 7. 边界

- 不编数据。没给数字就用可验证的模糊量，或者直接问。
- 医疗、金融、教育不写具体效果承诺。
- 不确定的事实标"待核实"，不写成结论。
- 不写"最/第一/唯一"这类绝对化表述，除非有可核验的来源。
