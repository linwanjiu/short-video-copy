# 场景库（喂给视频流水线）

文案要变成视频，就得从"一段话"拆成"一个个场景"。每个场景对应视频里的一屏。
类型只有五种，换来换去就是这五种版式。

## 五种类型

| type | 用途 | 文字上限 | 备注上限 | 最少停留 |
|---|---|---|---|---|
| `title` | 开场标题屏 | 10 字 | 18 字 | 2.2s |
| `point` | 一个论点 / 一句口播 | 12 字 | 20 字 | 1.4s |
| `stat` | 数据卡（1–3 张） | — | — | 1.8s |
| `quote` | 可截图的金句 | 12 字 | 20 字 | 2.0s |
| `outro` | 收口 / CTA | 5 字 | 20 字 | 2.2s |

**12 字是硬上限**，不是建议。算法：4.2 字/秒 + 逗号 0.2s + 句号 0.35s。
12 字带一个逗号一个句号 = 3.41 秒，刚好卡在单镜头 3.5 秒内。
14 字就要 3.88 秒，视频侧只能压字号或拉长镜头，节奏会散。

## 从文案结构映射到场景

| 文案里的一段 | 变成什么 |
|---|---|
| 钩子（第一句） | `title`（如果它够短够狠）或 `point` |
| 每个论据 / 机制 | 一个 `point` |
| 数字、对比、比例 | `stat`（1–3 张卡） |
| 那句能截图的话 | `quote` |
| 结尾动作 | `outro` |

## 顺序

```
title → point × N → stat（可选，放数据出现的位置）→ quote → outro
```

- 首段必须是 `title`，末段必须是 `outro`
- `stat` 不一定要有；没有具体数字就别硬凑
- 同一类型连续出现不要超过 3 个，否则版式单调

## 段数

| 时长 | 段数 |
|---|---|
| 15 秒 | 5–8 段 |
| 30 秒 | 8–14 段 |
| 45 秒 | 12–18 段 |

段数 = 场景数。视频侧按它切段、排时间轴，所以**段数就是剪辑的颗粒度**。

## 例子

一句话选题「为什么你总是睡不够」，出一段 30 秒的：

```json
{
  "style": "simple",
  "title": "越补觉越累",
  "scenes": [
    { "type": "title", "kicker": "睡眠债的真相", "text": "越补觉，越累", "note": "你欠的不是时间" },
    { "type": "point", "text": "睡不够，欠的不是时间，是节奏" },
    { "type": "point", "text": "周末睡到中午，等于每周倒一次时差" },
    { "type": "point", "text": "咖啡不是提神，是把困意记账" },
    { "type": "stat", "items": [
      { "value": 8, "suffix": "h", "label": "常被误读" },
      { "value": 1, "suffix": "条", "label": "真正的标准" }
    ]},
    { "type": "quote", "text": "睡够不是八小时，是同一时间醒" },
    { "type": "outro", "kicker": "这周先做", "text": "改起床", "note": "关注我，把作息调回来" }
  ]
}
```

这段在视频侧会被切成 7 段，总时长约 18 秒（视频侧会按字数算，不是按上面这张表）。

## 写完必须校验

```bash
node scripts/check-scenes.mjs content.json
```

它会检查：类型是否合法、字数是否超限、数据卡数量、首尾场景、估算时长。
不通过就不要交给视频侧——那边会把它渲染成一堆压字或者超时的镜头。
